CPU vs GPU

The CPU is a few brilliant generalists; the GPU is thousands of simple workers doing the same thing in lockstep. Running a neural network (a chatbot, an image generator, a speech recogniser) is almost entirely "the same simple operation on huge piles of numbers", which is exactly what GPUs are built for.

  • Explain why GPUs win at matrix multiplication and lose at branchy, sequential code.

1. What a CPU core does

A CPU core repeats one loop billions of times per second: fetch the next instruction from memory, decode what it asks, execute it (add two numbers, compare, jump, load, store), then write back the result. An instruction is tiny: "add register 3 to register 5". Programs in any language are eventually translated to millions of such instructions (Module 5).

  • Clock speed (e.g. 3.5 GHz) = how many ticks per second. More ticks, more instructions.
  • Cores = independent workers. A laptop has 4–16; a server up to 128+.
  • CPU cores are smart: they guess which way an if will go (branch prediction), reorder instructions, and keep big caches, so even complicated, unpredictable code runs fast.

2. What a GPU does differently

Graphics needs the same small calculation on millions of pixels. GPUs therefore trade cleverness for numbers: thousands of simple cores, each slower and dumber than a CPU core, grouped so that 32 or so run the same instruction at the same time on different data (called SIMT/SIMD: "single instruction, multiple data"). If threads in a group want to take different if branches, the group runs both paths one after another ("divergence"), and the speed advantage collapses.

Take-away: A GPU is not "a faster CPU". It is a different tool. Same operation × millions of items → GPU wins by 10–100×. Complicated decisions per item, or little data → the CPU wins, and copying data to the GPU might cost more than the work saves.

3. Matrix multiplication: the heart of AI

What a layer does, in plain words. Imagine 3 input numbers and 2 output numbers. Each output is a weighted sum of the inputs: "2 parts of the first input, minus 1 part of the second, plus half of the third". The weights are the learned numbers (Module 11). Do this for every output and you have a matrix multiplication. A model stacks dozens of such layers with small non-linear tweaks between them, and that stack is the "intelligence". Nothing more mysterious happens inside than multiplying and adding at huge scale.

A neural network layer is mostly y = x @ W: a matrix multiplication. Multiplying two n × n matrices takes about 2n³ floating-point operations (FLOPs: multiplies and adds). Doubling n makes it 8× more work. Hardware speed is quoted in FLOP/s: a laptop CPU gives ~100–500 GFLOP/s, a gaming GPU ~20–80 TFLOP/s, a data-centre GPU several hundred TFLOP/s in 16-bit formats.

4. What it costs to produce one word

A chatbot writes its reply one token at a time (Module 11). For each token, every one of the model's parameters takes part in the arithmetic (about one multiply and one add each), so:

work per token ≈ 2 × parameters  →  7B model: 2 × 7×10⁹ = 14 billion operations per token.

A 300-token answer is 300 × 14 GFLOP ≈ 4 TFLOP. On a laptop CPU doing ~200 GFLOP/s that is ~20 s of pure arithmetic, so a few seconds on a gaming GPU at 20–80 TFLOP/s is a big difference. That gap is why AI runs on GPUs.

There's a second limit, memory: for each token the GPU must also read all 14 GB of weights from its memory. A GPU with ~1,000 GB/s of memory bandwidth needs 14 ms for that read, which caps generation at roughly 70 tokens per second no matter how fast its cores are. This is the same bandwidth idea as Module 2, and it explains why:

  • Smaller (quantised) models generate faster as well as fitting in less memory (Module 1).
  • Replies stream word by word at a steady speed, regardless of how simple the question was.
  • Big models need several GPUs, partly to hold the weights and partly to add memory bandwidth.

Other accelerators (TPUs, phone NPUs, Apple's Neural Engine) follow the same recipe: specialise the chip for matrix math and feed it fast memory.

# Try it: time one big matrix multiplication on CPU vs GPU (needs PyTorch; the GPU part needs an NVIDIA GPU or Colab)
import torch, time
n = 4096
a, b = torch.randn(n, n), torch.randn(n, n)
t = time.time(); a @ b; print("CPU:", time.time() - t)
if torch.cuda.is_available():
    a, b = a.cuda(), b.cuda()
    a @ b; torch.cuda.synchronize()        # warm-up (first call is slow)
    t = time.time(); a @ b; torch.cuda.synchronize()   # GPU runs asynchronously!
    print("GPU:", time.time() - t)

GPU calls return immediately while the work runs in the background. Always call torch.cuda.synchronize() before stopping the timer, or you'll measure nothing and think the GPU is infinitely fast.
