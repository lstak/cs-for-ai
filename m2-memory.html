Memory & storage

A computer is not one pool of memory but a pyramid: tiny and blazing fast at the top, huge and slow at the bottom. Where a piece of data lives (a model's weights, your documents, a chat history) decides how quickly an AI system can use it.

  • Name the levels of the memory hierarchy and their rough speed and size.
  • Explain why a chatbot model has to be loaded into GPU memory before it can answer anything.
  • Estimate how long it takes to load a model or a document collection from disk, network or RAM.
  • Explain latency vs bandwidth, and why a "cache" makes repeated work fast.

1. The workshop analogy

Imagine a carpenter (the CPU). Tools in her hands are instant (registers). Tools on the workbench take a second (cache). Tools in the garage take a minute (RAM). Tools in the warehouse across town take hours (SSD/disk). Tools ordered from another country take weeks (network). A good carpenter keeps what she needs close and fetches in batches. A computer does the same. A chatbot is the same story: the model's weights are the carpenter's tools, and they must be fetched from the warehouse (disk) to the workbench (GPU memory) before work can start.

2. Latency vs bandwidth

Latency is how long until the first byte arrives. Bandwidth is how many bytes per second flow once it starts. A cargo ship has huge bandwidth and terrible latency; a motorbike courier the opposite. Reading one tiny file from a network drive is latency-bound; copying a huge file is bandwidth-bound. Many small reads are the worst case: opening 100,000 tiny text files is far slower than reading one big file of the same total size.

3. Caches and why access order matters

When the CPU reads one number from RAM, the hardware grabs the whole surrounding 64-byte cache line (e.g. 8 neighbouring doubles), betting that you'll want the neighbours next. If you walk through memory in order, 7 of every 8 reads are cache hits. If you jump around, nearly every read is a slow miss. 2D arrays are stored row after row, so walking along a row is sequential and walking down a column is a series of jumps.

"Cache" is a general idea. Keep a copy of something you'll need again somewhere closer and faster. AI services do this everywhere: a model stays loaded in GPU memory between requests instead of reloading; a chat service keeps the already-processed start of your conversation so it doesn't redo it for every message ("prompt caching"); a search feature keeps hot document embeddings in RAM. All of them trade scarce fast memory for time.

4. GPU memory is a separate pyramid

A GPU has its own memory (VRAM or HBM), physically separate from the computer's RAM. Running a model means: (1) the weights sit in a file on disk, (2) they are read into RAM, (3) they are copied across a bus (PCIe, Module 9) into VRAM. Only then can the GPU start answering. That is why a local chatbot takes many seconds to start, why the first request to a cold server is slow, and why a bigger model needs a GPU with more VRAM (typically 8–80 GB). If the model plus the conversation doesn't fit you get an error such as CUDA out of memory, no matter how much RAM or disk you have. More in Modules 3 and 10.
