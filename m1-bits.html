Bits, bytes & numbers

A computer only knows switches that are on or off. Everything an AI system touches (your words, a photo, a voice recording, the model itself) is a convention for reading patterns of switches. A model never sees a sentence or a face, only numbers.

  • Explain what a bit and a byte are, and convert between binary and decimal.
  • Explain how text, images and audio become the lists of numbers that AI models work on.
  • Explain why 0.1 + 0.2 != 0.3 and what fp32, fp16, bf16 and 4-bit formats trade off.
  • Estimate how big a model's file is, and whether a given chatbot model can run on your laptop.

1. The bit and the byte

A bit is one switch: 0 or 1. A byte is 8 bits. With 8 bits you can make 2⁸ = 256 different patterns. What the pattern means depends entirely on how the program chooses to read it: as a whole number, a letter, a pixel brightness, or part of a decimal number.

Binary works like decimal, except each position is worth a power of 2 instead of a power of 10: 1, 2, 4, 8, 16, 32, 64, 128.

Interactive: the bit flipper

Click bits to flip them. Watch the same 8 switches be read as different things.

Signed numbers. To store negatives, computers use two's complement: the top bit counts as −128 instead of +128. That is why the same pattern 11111111 is 255 unsigned but −1 signed. Try it above.

Image pixels are usually one byte per channel (0–255). That is why you divide by 255 to normalise images, and why uint8 overflows if you do arithmetic on it carelessly: np.uint8(250) + np.uint8(10) gives 4, not 260.

2. Text is numbers too

Each character gets a number (ASCII/Unicode): A is 65, a is 97. Modern text uses UTF-8, where common letters take 1 byte and others (é, 你, 😀) take 2–4. Language models add another layer on top: a tokenizer chops text into pieces and gives each piece an integer id. That list of ids is what the model actually receives (Module 11 shows how it is used).

print(ord("A"), chr(66))          # 65 B
print(len("hello".encode("utf-8")))   # 5 bytes
print(len("你好😀".encode("utf-8")))   # 10 bytes for 3 characters

3. Images and sound are numbers too

The same idea covers everything else a model can perceive:

DataHow it becomes numbersExample size
TextChopped into tokens, each an integer idA 10-word sentence ≈ 13 numbers
ImageA grid of pixels; each pixel is 1 number (grey) or 3 (red, green, blue), each 0–255224 × 224 × 3 = 150,528 numbers
AudioThe air-pressure wave is measured many times a second (the sample rate); each measurement is one number1 second of speech at 16,000 samples/s = 16,000 numbers
VideoA stack of images, plus the audio30 images per second
The model itselfBillions of learned numbers (the weights)7,000,000,000 numbers

So when an image classifier, a speech-to-text system or a chatbot "looks at" something, it receives a long list of numbers, and the "magic" is a function (Module 11) that turns one list of numbers into another.

4. Numbers with decimals: floating point

To store 3.14159 or 0.0000012, computers use a binary version of scientific notation: a sign, an exponent (how big), and a mantissa (the significant digits). The number of bits given to each decides the range and the precision.

FormatBitsExponent / mantissaApprox. rangeDecimal digitsTypical AI use
fp64 (double)6411 / 5210±308~16Python's default float
fp32328 / 2310±38~7Classic training

Key lesson: most decimal numbers cannot be stored exactly, just like 1/3 cannot be written exactly in decimal. 0.1 is an endless repeating fraction in binary, so the computer stores the nearest representable value. The error is tiny, but it exists.

print(0.1 + 0.2)            # 0.30000000000000004
print(0.1 + 0.2 == 0.3)     # False!
import math
print(math.isclose(0.1 + 0.2, 0.3))   # True: always compare floats with a tolerance

Why so many formats? A model is billions of numbers, and each one costs bytes. Storing each number in fewer bits makes the model smaller, so it fits on cheaper hardware. Quantisation means converting a model's weights to a smaller format (say 16 bits down to 4). You lose a little precision, and the answers usually change very little. That is how a chatbot model that needs 14 GB in fp16 can run on an ordinary laptop in 4-bit form (about 3.5 GB). The two 16-bit formats differ in what they sacrifice: fp16 keeps more precision but overflows above 65,504, while bf16 keeps fp32's huge range with less precision.

5. How big is a model?

Memory = (number of parameters) × (bytes per parameter). A 7-billion-parameter model:

FormatBytes/paramWeights only
fp32428 GB
fp16 / bf16214 GB
int817 GB
int40.53.5 GB

This is the size of the download and the memory needed just to run the model (inference). Training needs several times more, because the computer must also store the corrections it is working out (Module 11), which is why training a model is done in data centres while using one can be done on a laptop or phone. The model also needs some extra memory for the conversation it is currently handling.
