Self-paced crash course

How Computers Work

Hardware, operating systems, software, networking, the Web, data and peripherals, plus how AI models, the cloud and AI agents actually work. Explained for AI practitioners with no computer-science background. Every idea comes with an interactive graphic and is tied to something you will meet when building or using AI.

Who this is for: you can write basic Python (variables, loops, functions, lists). You do not need to know anything about hardware or networks.

How long: about 45–60 minutes per module, 13 modules. Modules 1–10 build the foundations in order (hardware, OS, software, networking, the Web, peripherals, and a capstone); Modules 11–13 (how AI works, the cloud, agents) use those foundations and can be read in any order afterwards.

The big picture: four layers

A computer system is built as a stack of layers. Each layer offers a simple service to the layer above and hides the messy details of the one below. You can use a chatbot without knowing how a GPU works, and write a web page without knowing how electricity moves through a cable. That is the idea that holds the whole course together.

Interactive: the layered architecture

Click any layer to learn what it does and which modules cover it. Press Send a request to follow one message (say, your chat question) down your computer's layers, across the network, and up the server's layers.

LayerWhat it isExamplesModules
ApplicationsThe programs you use or write. They ask the layers below for help.Browser, chat app, Python script, web server, AI model server, agent5, 7, 9, 10, 12
NetworkingAgreed rules (protocols) for machines to exchange data, so a message can cross the world.DNS, TCP/IP, TLS, HTTP6, 7
Operating systemThe manager. Shares the hardware between programs and keeps them apart. Also contains the software that runs the network protocols.Linux, Windows, macOS, WSL24
HardwareThe physical machine, where everything is finally bits and electricity.CPU, GPU, RAM, SSD, network card, camera, microphone1, 2, 3, 8

A simplification, honestly stated. The network software actually lives inside the operating system (and the network card), but it is such an important idea (it is how two stacks talk to each other) that we draw it as its own layer. Also, real systems have more layers than four; this is the map, not the territory.

Why layers matter for you: when something goes wrong, the first question is which layer? "Connection timed out" is networking, "Killed" is the operating system, "CUDA out of memory" is hardware, and a wrong answer from a chatbot is the application (the model). Modules 12 (the cloud) and 12 (agents) build on all four layers, and Module 10 follows one message through every one of them.

How to learn from this course

What you will be able to do afterwards

  • Read an error such as 429 Too Many Requests, CUDA out of memory, Killed or Connection timed out and know which layer it came from.
  • Explain how text, images and sound become numbers, and how big an AI model really is.
  • Explain how a website and a web API work (HTTP, HTML/CSS/JS, rendering, REST, WebSockets) and how a chat app talks to an AI model.
  • Follow one chatbot message from keyboard to screen and say what each layer does.
  • Make rough size, time and cost estimates for running an AI model (a laptop, a rented GPU or an API) with reasons, not folklore.
  • Explain, in plain words, how a chatbot turns text into numbers, predicts an answer, and why it can be confidently wrong.
  • Describe an AI agent (the loop, tools, MCP) and judge its risks and costs.
  • Choose between a hosted model API and renting your own cloud GPU, with a rough cost estimate.
  • Talk to engineers and cloud/IT teams in their vocabulary.

Numbers in the simulations are realistic orders of magnitude, simplified for teaching; real hardware varies.
